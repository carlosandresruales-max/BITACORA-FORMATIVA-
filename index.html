⚙️ Configuración del sistema

💡Solo Administrador y Rectoría pueden ver y modificar esta sección.
Debe terminar en /exec. El mismo Apps Script maneja Sheets y la subida de anexos a Drive (ver Codigo.gs entregado aparte).
Debe coincidir exactamente con la propiedad BACKEND_TOKEN configurada en Apps Script (Configuración del proyecto → Propiedades del script). Protege contra quien descubra la URL por accidente — no contra alguien que ya usa esta aplicación y revisa el código de su navegador. Para esa protección, vea la nota sobre "restricción por dominio" más abajo.
Cuentas institucionales · Activación del personal
🔐Solo Rectoría o Administración Técnica. Las invitaciones se generan únicamente para personal previamente autorizado en Supabase con correo y documento confirmados. Primero use Revisar pendientes; el envío requiere una segunda confirmación explícita.
👥Selección manual obligatoria. Primero cargue el personal elegible y luego elija exactamente a quién desea invitar. El lote piloto admite entre 1 y 5 personas. El sistema no escogerá usuarios automáticamente.

Protección de datos del backend (Sheets/Drive)
🔒La clave de arriba solo detiene accesos accidentales o automatizados desde fuera. Para bloquear de verdad el acceso a quien no sea del colegio, en el Apps Script (Implementar → Gestionar implementaciones) cambien "Quién tiene acceso" de "Cualquier usuario" a "Cualquier usuario de [su dominio]" — esto solo funciona si la institución tiene Google Workspace for Education con cuentas propias (no Gmail personal). Sin eso, cualquiera con la URL puede leer los datos si no configura la clave de arriba.
Ingreso con Google

Pendiente de habilitar — requiere que Rectoría/TI cree un "Client ID" en Google Cloud Console y defina el correo institucional de cada usuario. El botón ya está reservado en la pantalla de ingreso.
